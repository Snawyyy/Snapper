# Session notes, 2026-10-08 to 2026-10-09

What was done, in order, and why. The newest state and the next steps
are always in `CLAUDE.md` under "Where we stopped".

## 1. Reviewed the open branches

Five branches were unmerged (no `gh` CLI here, so they were plain
branches): `cut-markers`, `link-movement`, `shot-length-seconds`,
`video-editing`, `warp-animations`. `cut-markers` stacks on
`video-editing`. Four review agents ran in parallel.

Real findings, checked by hand:

- `link-movement`: duplicating a shot turned a link to a missing layer
  into layer id 0. Fixed, dropped dead links, test added.
- `warp-animations`: the possible divide by zero was a false alarm
  (a zero-size grid is never "on"). Asserts and a test now state it.
- `video-editing`: the export crash on a deleted shot could not happen
  (the reel lookup already gives such a clip length 0). The renderer now
  skips it anyway, with a test.
- `shot-length-seconds`: huge seconds overflowed to infinity and tripped
  an assert in debug. Now clamps, with a test.
- Many "named bool in `if`" and "two asserts per function" breaks on the
  lines each branch added. All fixed.

## 2. Fixed the linter

`snawys_lint.py` (in the `snawys_law` plugin repo, not here) skipped
every function inside a namespace, which is all of Snapper, so the
assertion and length checks never ran. Fixed, and now Qt Test checks
(`QVERIFY`, `QCOMPARE`, ...) count as assertions. The plugin now also
tells sessions and agents the linter's full path at start.

Result: about 163 old rule breaks on main became visible (89 in `src`,
74 in test helpers). That is why the `lint` ctest fails everywhere.
New lines add none. Pushed on the plugin repo branches
`codex-native-skill-port` and `fix-linter-namespaces`.

## 3. Integration branch `ui-test`

All five fixed branches were pushed and merged into `ui-test` (cut from
main) so the UI can be tested change by change. Conflicts (CMake source
lists, `ARCHITECTURE.md`, manager lists) were resolved by keeping both
sides.

Change made on top, on `link-movement`: drag nodes (warp points that
trail) now feel links, via `LinkShifts` passed into `DraggedPoses` and
`ShownPoses`. Test `DragNodesFeelLinks`.

## 4. UI feedback round, five changes

1. `link-movement`: the Link panel shows only when the picked thing
   follows something.
2. `video-editing`: the mode tabs moved into a fixed toolbar so they no
   longer slide sideways on the Video tab (test `TabsStayPutInEveryMode`).
3. `warp-animations`: motion now belongs to single warp points, picked
   like drag nodes, in a "Dot animation" panel. Old whole-piece motion
   files convert onto the dots they moved.
4. `cut-markers`: the Video timeline got full picking, split (S),
   delete, ripple remove (Shift+Delete), copy, cut, paste, duplicate,
   a right-click menu.
5. `cut-markers`: transitions moved off the shot onto the cut between two
   touching clips; double-click the cut to change kind and length. Old
   shot transitions move onto the matching reel cuts. Project file
   version is now 3.

Selection color is Teto red (rules in `CLAUDE.md` and `ARCHITECTURE.md`
fixed on branch `selection-red`).

## 5. UI rethink (design only, no app code yet)

Goal: Snapper should feel like a fun tool, not a calculator. Look
chosen: "Win98 but juicier" (keep dark Win98 and Teto red, add bouncy,
game-like feedback).

Everything lives in `docs/redesign/` (open the html files in a browser):

- `ui-ideas.md`: two separate ranked lists, Figma ideas and game-feel
  ideas, each placed on a Snapper screen.
- `index.html`: the design doc (principles with numbers, every
  screen, build order). `inventory.md`: all 295 controls in the
  app; the doc covers every one.
- `proto/index.html`: a playable HTML prototype, hub plus shared kit and
  six screen pages (shell, stage, timeline, inspector, rig, video).
  Checked by scripted headless clicks only, not yet with a real mouse.

The doc's first build steps: a motion table with a Full/Calm/Off Motion
setting; drag a field's label to change its number, and math typed in
fields; hover outline, bigger grab zones, 4 px drag start.
